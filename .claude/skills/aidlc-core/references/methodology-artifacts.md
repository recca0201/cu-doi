# MTV AI-DLC Artifacts

Complete artifact structure and file organization.

## Directory Structure

```
aidlc-docs/
├── foundation/              # Phase 0: Project context (5 files)
├── story-artifacts/         # Phase 1: User stories
├── requirements/            # Phase 1: Units, NFRs, risks
├── roadmap/                 # Phase 1: Timeline (optional)
├── design-artifacts/        # Phase 2 support: UX specs and mockups for UI-bearing units
├── specs/                   # Phase 2: Per-unit specs
│   └── {unit-slug}/        # requirements.md, design.md, tasks.md
├── operations/              # Phase 3: Deployment & monitoring
└── aidlc-state.md          # Workflow state tracking
```

## Foundation Artifacts (Phase 0)

| File | Agent | Command | Contents |
|------|-------|---------|----------|

| `uiux-guideline.md` | AI Design Orchestrator | `/aidlc.foundation.uiux-guideline` | UI components, colors, typography, design patterns |

## Inception Artifacts (Phase 1)

| File | Agent | Command | Contents |
|------|-------|---------|----------|
| `story-artifacts/{id}_{feature-name}_user_stories.md` | AI Assistant Product Owner | `/aidlc.inception.user-stories` | User stories (EARS-Lite), acceptance criteria, personas, dependency graph |
| `design-artifacts/{feature-name}_story_ux_design.md` (optional) | AI Design Orchestrator | `/aidlc.construction.ux-design` or equivalent AI Design Orchestrator workflow | Story-level user flows, rough wireframes, interaction patterns, accessibility guidance used to clarify scope before decomposition |
| `design-artifacts/prototype/{feature-name}/` (optional) | AI Design Orchestrator | `/aidlc.construction.ux-design` or equivalent AI Design Orchestrator workflow | Early HTML prototype for stakeholder validation when story-level UX needs visual review |
| `requirements/{id}_{feature-name}_units_decomposition.md` | AI Solutions Architect | `/aidlc.inception.decompose-units` | Technical units, dependencies, priorities, execution sequence |
| `requirements/nfr_requirements.md` | AI Assistant Product Owner | — | Performance, security, accessibility, scalability requirements |
| `requirements/risk_register.md` (optional) | AI Delivery Manager | `/aidlc.inception.risks` | Risk identification, impact assessment, mitigation strategies |
| `roadmap/product_roadmap.md` (optional) | AI Delivery Manager | `/aidlc.inception.roadmap` | Timeline, Gantt chart, milestones, validation checkpoints |

**ID Format**: 3-digit sequential (001, 002, 003...)

## Construction Artifacts (Phase 2)

Support artifacts for UI-bearing units:

| File | Agent | Command | Contents |
|------|-------|---------|----------|
| `specs/{unit-slug}/mockup.html` | AI Design Orchestrator | `/aidlc.construction.ux-design` | HTML UI handoff for implementation: visible states, component mapping, MDS traceability, responsive/accessibility structure |
| `design-artifacts/prototype/{unit-slug}/` (optional) | AI Design Orchestrator | `/aidlc.construction.ux-design` | Interactive HTML prototype for stakeholder visual validation |

Per-unit specs in `specs/{unit-slug}/`:

| File | Agent | Command | Contents |
|------|-------|---------|----------|
| `requirements.md` | AI Assistant Product Owner (Step 0)<br>AI Solutions Architect (Step 1) | `/aidlc.construction.plan-bolts`<br>`/aidlc.construction.refine-requirements` | User stories for unit, acceptance criteria, constraints, scope, dependencies |
| `design.md` | AI Orchestration Engineer | `/aidlc.construction.create-design` | Technical design, API contracts, data models, UX flows, diagrams |
| `tasks.md` | AI Orchestration Engineer | `/aidlc.construction.create-tasks` | Implementation tasks, dependencies, complexity, sequence, acceptance criteria |

**Unit Slug**: kebab-case (e.g., `auth-service`, `payment-gateway`)

**Note**: `requirements.md` generated by Bolt Planning (Step 0) for ALL units, then refined per unit (Step 1)

## State Tracking

**File**: `aidlc-state.md`

**Created by**: AI Delivery Manager
**Updated**: After each step by any agent
**Format**: YAML frontmatter + Markdown

**Tracks**: Workflow ID, current phase/step, user intent, completed steps, validation checkpoints, next action

---

## File Naming

**User Stories**: `{id}_{feature-name}_user_stories.md`
- Example: `001_authentication_user_stories.md`

**Units Decomposition**: `{id}_{feature-name}_units_decomposition.md`
- Example: `001_authentication_units_decomposition.md`

**Spec Files**: `{unit-slug}/{type}.md`
- Example: `auth-service/requirements.md`

**IDs**: 3-digit sequential (001, 002, 003...)
**Names**: kebab-case

---

## Documentation Formats

- **Text**: Markdown (.md)
- **Diagrams**: Mermaid (architecture, flows, Gantt, ER)
- **Config**: YAML
- **Data**: JSON

---

## Organization Principles

1. Phase-based folders (foundation, inception, construction, operations)
2. Sequential 3-digit IDs for ordering
3. Descriptive filenames with feature/unit names
4. Flat structure (max 2 levels deep)
5. Single source per artifact
